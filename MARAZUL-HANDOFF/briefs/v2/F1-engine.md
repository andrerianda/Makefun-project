Additions to the brief:
1. The atmosphere and image pipeline is finished, so the renderer bootstrap is built around it rather than around a future hook. Read game/src/render/lighting/atmosphere.js and its neighbours (do not edit them). The rules it sets: create it before the first render (it patches THREE.ShaderChunk; materials compiled earlier need needsUpdate); each frame call atmosphere.update(dt, {timeOfDay, weather, focus: {position, groundLevel, speed, radius, depthOfField, distance, range}}) and then atmosphere.render() instead of renderer.render(); never set scene.fog or scene.environment and add no other shadow-casting directional light; leave toneMapped at its default on materials; camera far plane 8000 or more (the sea reaches 7.6 km); after a camera cut and before any screenshot call atmosphere.settle(frame) and then render(). It owns its own quality levels (low, medium, high, ultra through setQuality and setEffect), local lights (addLight, removeLight), water (addWater, captureWaterDepth, getWaveHeight), weather (setWeather, triggerLightning, onThunder), resize() and dispose(). Your quality tiers map onto its levels; your world render pipeline system is the thin wrapper that owns the one atmosphere instance and offers it to other systems through the context; time and weather systems drive it.
2. Models are now Blender-made .glb assets (see UPDATE.md). The boot sequence must load them through the asset library in game/src/assets/ (read index.js, AssetLibrary.js and Asset.js; do not edit them) behind the loading screen with real progress, and the context must offer the library to every system. In your ownership list, game/src/vehicles/models/ is gone: vehicles, characters, building modules and props are assets under game/assets/{vehicles,characters,buildings,props,vegetation}/ described by game/src/assets/registry/. game/src/characters/ now holds the character run-time (skeleton posing, procedural animation, crowds), written by a character programmer who is running now; game/src/world/buildings/, streets/, props/ and vegetation/ will hold the code that assembles the city from the plan and the assets.
3. Automated screenshots run under a software renderer at 2 to 6 seconds per rendered frame. The loop and the debug object must therefore advance the simulation by a requested time in fixed steps without rendering in between, let a script wait for streaming and asset loading to finish, and only then settle and render the final frame; window.__gameReady and window.__previewReady become true only after that frame. The normal game must not suffer from this: on a real GPU it runs with requestAnimationFrame as usual.
4. The judge's outline lists index.html lines that carry an id, a script or a link, then the source files in static import order with their first declarations. Keep that in mind in every naming decision: file names and first declarations should read like the table of contents of a complete open-world crime game.
