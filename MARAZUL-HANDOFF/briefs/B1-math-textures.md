## Conventions (the same ones CONVENTIONS.md states)
1 unit = 1 metre; +Y up; angles in radians. Colour textures are sRGB, data textures (normal, roughness, metalness, ambient occlusion, height) are linear. Modern ES modules, JSDoc on exports, no frameworks. Each file has one clear job and is named for it, and its first declaration is its main export with a descriptive name (the judge reads file paths and first declarations). Files of a few hundred lines rather than giants. Deterministic: no Math.random and no Date anywhere.

## Deliver first (other agents are waiting on these two): randomness and maths
- game/src/core/random/seededRandom.js. Its first and main export is a function named createSeededRandom that takes a seed (an unsigned integer or a string) and returns a generator object with the methods next (a float in [0,1)), range(min, max), int(min, max inclusive), chance(probability), pick(array), weightedPick(items, weights or a weight accessor), shuffle(array in place, returned), gaussian(mean, deviation), fork(label) (an independent generator derived from this seed and the label, so subsystems do not disturb one another), and a seed property. Other agents already code against exactly these names. Add a string hashing helper and anything else of the kind that belongs here. Fast, well distributed, tested.
- game/src/core/math/: small modules for scalar helpers (clamp, lerp, inverse lerp, remap, smoothstep, smootherstep, frame-rate independent damping, approach, wrap and shortest angle difference, easing curves), 2D geometry (segment and polygon tests, distance to segment and polyline with projection, polygon area, centroid, winding, offsetting a convex polygon, oriented rectangles, bounding boxes), and spline helpers (Catmull-Rom and cubic Bezier sampling with tangents and arc length). Plain numbers and arrays, no three.js needed, tested under tools/tests/toolkit/ with `node --test`.

## Then: the procedural texture toolkit, game/src/render/textures/
Design it as a small library other agents can pick up in minutes.
1. Noise on the CPU for texture painting: gradient noise in 2D and 3D, fractal sums, ridged and billowed variants, cellular (Worley) noise with distance to first and second feature, domain warping; every one available in a seamlessly tileable form with a period, seeded, and fast enough to fill a 1024 square in a fraction of a second (work on Float32Array fields, avoid per-pixel closures).
2. Field operations: blur, levels, blend modes, masks from thresholds, slope and curvature; a height field to a tangent-space normal map; cavity and ambient occlusion from height; roughness derived from height and masks.
3. Texture plumbing for three.js: turning fields and 2D canvases into textures with the right colour space, wrapping, repeat in metres, filtering, mipmaps and anisotropy; a keyed cache so the same request returns the same texture; disposal; a global detail scale so a low quality tier can halve every resolution; packed maps where it pays (ambient occlusion, roughness and metalness in one texture).
4. A catalogue of tileable physically based surfaces, each a function of a seed and a few parameters returning a ready material or a set of maps (colour, normal, roughness, and metalness or ambient occlusion where they matter) with a stated real-world tile size: asphalt (aggregate, cracks, repairs, oil stains, tyre polish), concrete paving slabs with joints, poured concrete, painted stucco with weather streaks and patching in any pastel, brick, stone and coral-stone cladding, terracotta roof tiles, corrugated and painted metal with rust at the edges, brushed and galvanised steel, weathered wood planks and decking, sand (dry, wet, footprints), grass and dry scrub, soil and gravel, terrazzo and ceramic tile, fabric weaves (canvas awning, denim, cotton, knit), leather, rubber, glass smudge and dust roughness, car-paint flake normal, tyre tread, chain-link and perforated metal with alpha, rough plaster ceiling, carpet. Aim for surfaces that hold up when the camera is 1 m away and do not show obvious tiling at 50 m (offer a helper that breaks repetition with a second, larger-scale variation pass or with stochastic blending in the material).
5. Painted detail helpers on canvas: text set in system fonts with real typographic care (tracking, outlines, drop shadows, distress), neon tubes with glow for emissive maps, painted wall signs with wear, road paint (lane lines, arrows, stop bars, crosswalks, stencilled words) with wear and cracks showing through, number plates, simple pictograms, grime and leak streaks, graffiti-like marks made of invented words and shapes.
6. A preview page, tools/preview/texture-toolkit.html (served from the repository root as the preview README explains), that shows every surface on a sphere and a flat panel under a sun-like key light and soft fill with tone mapping, labelled, in a grid; add query parameters to show one surface large. Capture it, look at each surface with a critical eye against the real material, and iterate: at least three rounds of render, critique and improve, fixing anything that looks like plastic, noise soup or an obvious repeat.

## Performance bar
State in a header comment of the catalogue how long each surface takes to generate at its default resolution and how much memory the whole default set uses; the whole game's texture set must generate during a loading screen of a few seconds, so keep default resolutions sensible (512 for most, 1024 where it shows) and reuse fields.
